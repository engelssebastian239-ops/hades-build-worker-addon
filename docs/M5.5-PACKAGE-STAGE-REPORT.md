# M5.5 Package Stage candidate

## Implemented

- A separate `/v1/package-stage` endpoint is added to the existing Build Worker.
- The feature gate `package_stage_enabled` defaults to `false`; absent or disabled feature state leaves the endpoint unavailable.
- The broker envelope binds an allowlisted private repository, immutable commit, exact Mobile package path, archive SHA-256, and bounded archive size to the existing worker identity.
- The receiver checks the signed envelope, digest, expiry, persistent replay state, strict file and expansion limits, and safe staging paths before writing.
- Only regular files and directories are accepted from ustar/gzip archives. Path traversal, duplicate names, links, special files, and trailing non-zero data are rejected.
- Staging is owner-only and does not execute or install package contents. No shell interface or extra host/API privilege is added.
- The existing diagnostic protocol and diagnostic route remain unchanged.
- The companion M3.5 integration is in private repository Draft PR #25. It accepts only owner-authored, exact-schema stage-only tasks, reads and verifies blobs at a pinned Git commit, constructs the bounded archive, dispatches through existing broker/worker identities, verifies the signed receipt, and records a GitHub result.

## Gate

This is code-only and remains in Draft PR #2. The matching M3.5 code remains in Draft PR #25, stacked on M5.4. Both runtime feature gates default to disabled. Neither PR is merged, and no runtime was changed or enabled. The staging feature cannot install or execute package contents.

## Persistent data path

The staging directory and its replay ledger are stored beneath the existing worker-owned `/data/hades-m42.5` directory, which the launcher prepares as mode 0700 and owns as UID/GID 1000 before dropping privileges. The separate `package-stage-ledger.json` does not replace or alter the existing `diagnostic-ledger.json`. A regression assertion covers both paths. No files were touched on a live instance.
