# M5.5 Package Stage candidate

## Implemented

- A separate `/v1/package-stage` endpoint is added to the existing Build Worker.
- The feature gate `package_stage_enabled` defaults to `false`; absent or disabled feature state leaves the endpoint unavailable.
- The broker envelope binds an allowlisted private repository, immutable 40-character commit, exact Mobile package path, archive SHA-256 and bounded archive size to the existing worker identity.
- The receiver checks the signed envelope, digest, expiry, replay state, strict file and expansion limits, and safe staging paths before writing.
- Only regular files and directories are accepted from ustar/gzip archives. Path traversal, duplicate names, symlinks, hardlinks, special files and trailing non-zero data are rejected.
- Staging is owner-only and does not execute or install package contents. No shell interface or extra host/API privilege is added.
- The existing diagnostic protocol and diagnostic route remain unchanged.

## Verification

- New package-stage tests: 4 passed. The local HTTP listener test is skipped because the workspace prohibits local TCP listeners.
- Existing add-on tests: 5 passed, 1 test blocked by the same environment restriction (`listen EPERM` in the pre-existing restart/identity integration test).
- `npm run syntax`: passed.
- No ARM64 build, Home Assistant install, live worker test, or GitHub-to-server roundtrip was performed.

## Gate

This worker-side candidate is not a complete autonomous bridge. The matching M3.5 task parser, pinned GitHub archive retrieval, broker dispatch, GitHub receipt, server bootstrap and runtime configuration are not implemented here. The feature remains disabled and the worker change must not be installed or enabled until the complete cross-repository path has been reviewed and tested.
