# M577 isolated Mobile plan worker

This is a separate source candidate based on the repository main snapshot. It does not replace or update the installed c406e920_hades_build_worker and does not change local_hades_dev_bridge. The new add-on has its own slug, /data/hades-mobile-plan-worker, Ed25519 identity, GitHub credential, ledgers, and internal route to c406e920-hades-m574-installer:8767.

Both add-ons start with execution disabled. The Worker still creates and reports its own public key when disabled so the Owner can enroll the two public identities without a task being processed. The Installer does the same and makes no Supervisor API request while enabled is false. Copy only the public ID and public key between the add-on option forms. Never copy a private key.

After both pins are exact, an Owner can enable mobile_plan_enabled locally on the new Worker and provision a fine-grained GitHub token through its authenticated Home Assistant ingress. Token validation checks the pinned private repository, Contents read, Actions read, and Issues read before storing the token with mode 0600. The credential is not an add-on option or environment value. A normal owner-authenticated PLAN issue may then produce a signed receipt containing only hashes, source/CI identifiers, and a plan ID.

mobile_install_enabled remains false by default and is checked by the Worker from its local add-on options before the INSTALL controller can run. Issue fields cannot change that switch. The Installer enabled flag is separately local and defaults false. Installation remains gated on reviewing both source candidates, checking the installed Supervisor is supported, confirming the AppArmor profile is actually enforced, and preserving the encrypted Installer data directory. No issue may enable either flag.

The Installer has the Supervisor manager role and a writable /addons mapping because Supervisor rebuild is required. AppArmor is intended to confine writes to the fixed Mobile target and named staging files. This is a broad Supervisor API permission bounded by the add-on profile; it is not a general worker permission. If the expected full AppArmor profile identity is not enforced, the Installer fails closed. The profile has not been verified on the owner's running host by this source PR.

Before a promotion the Installer creates an encrypted partial Supervisor backup and an encrypted exact source snapshot. Supervisor partial backups also include Supervisor configuration and repositories; the adapter never invokes partial restore automatically. A confirmed build failure can restore the exact previous Mobile source and rebuild it. A timeout or interrupted build becomes UNKNOWN and blocks further mutation until reviewed reconciliation. This is source rollback only; it does not restore Mobile user data or guarantee rollback if Mobile later gains data migrations.

Before removing the Installer, first make a protected Home Assistant backup that preserves the add-on's private /data/hades-m574-installer directory. That directory contains the encryption key needed to read its source snapshots and backups. Disable the add-on, stop it, preserve that data, then remove it only after recovery material is verified. Do not paste keys into chat, issue bodies, logs, or shell output.

The checked M574 source is pinned in code to commit addf609d98256e989e1fc7b2f833d80f95628ae7, CI run 40190750157, and the fixed package path. The actual canonical M574 package/archive hash is generated by the verified PLAN operation; it is not a static value and this source PR does not claim a package has been installed. The known source package omitted a real studio-night.png in the local snapshot, so do not build a substitute package from that incomplete copy.

The M577 workflow checks out the exact pull request head SHA, downloads that commit's public GitHub codeload tarball with a 16 MiB response limit, and prints its SHA-256. It also prints a bounded path/mode/Git-blob-SHA/file-SHA manifest and a manifest SHA-256 for each new add-on. It uploads no archive or artifact. To verify a published source snapshot on a connected staging device, copy the exact commit SHA and archive SHA from that successful run, then run `curl --fail --proto '=https' --max-redirs 0 --max-filesize 16777216 --output m577-source.tar.gz https://codeload.github.com/engelssebastian239-ops/hades-build-worker-addon/tar.gz/<commit-sha>` into a private staging directory. Check it with `printf '<archive-sha256>  m577-source.tar.gz\n' | sha256sum -c -` before opening or extracting it. A mismatch means discard the staged archive and stop. Compare the emitted per-addon manifest with the files selected for staging; do not use the moving main branch or a PR merge ref. Keep the archive and staging copy separate from `/addons` until both pins, Supervisor version and enforced AppArmor profile have been reviewed.

For a future authorized install, the Owner must first confirm the exact archive and manifest hashes, make sure the add-ons are pinned to each other's newly generated public identities, and preserve the encrypted Installer data directory. The Installer itself makes its encrypted partial backup immediately before promotion. On a confirmed failed build it restores only the saved Mobile source and rebuilds once. If a request or rebuild becomes UNKNOWN, stop and reconcile its signed job status; do not resend the INSTALL issue. Do not run a manual source replacement or a Supervisor partial restore as a shortcut. No installation instructions are executable from this PR because the public M577 head, its CI hash output, host profile enforcement and owner-side backups do not yet exist.

The public PR workflow runs synthetic regression tests and builds ARM64 images with QEMU on standard Ubuntu runners. It publishes no image, cache, or artifact. A passing run proves source/build behavior only; it does not provision add-ons, validate the host AppArmor profile, establish a working GitHub credential, or prove a HADES↔HERMES chat round trip.
